# AI 出海模块维护说明

入口：`/module/ai-overseas`，位于首页和导航的 AI 拼团之后。

## 内容放在哪里

| 要改什么 | 文件 |
| --- | --- |
| 九阶段路线、任务、验收、例子、模板 | `src/content/overseas.ts` 的 `OVERSEAS_STAGES` |
| 阶段分组、知识点和参考资料 | 同文件的 `OVERSEAS_PHASES`、`OVERSEAS_TERMS`、`OVERSEAS_RESOURCES` |
| 路线图、阶段详情、知识库、实战记录、模板页面 | `src/pages/OverseasPage.tsx` |

| 首页九阶段全景图与回退分支 | `src/components/overseas/OverseasRoadmap.tsx` |
| 首页连贯阅读的九阶段正文 | `src/components/overseas/OverseasGuide.tsx` |
| 布局与手机适配 | `src/pages/overseas.css` |
| 个人勾选进度 | `src/hooks/useOverseasProgress.ts` |

这是独立的学习专区。路由、首页入口、全站搜索与现有站点集成，内容无需套用旧课程结构。

专区首页直接展示完整路线说明：全景流程图（含需求验证回退、复盘进入下一轮）、实践方式、提前开展的事项、九阶段目标与产出、具体任务、验收、例子、卡点与处理、第一步行动。所有正文默认展开，与 Markdown 导出共用阶段数据，不把完整说明藏在下载或多个详情页中。

点图中的阶段可跳到本页正文；正文再链接到勾选实践页与模板。桌面用连线全景图，手机用竖排流程和同样的判断分支。离线复制、下载放在“模板与工具”的可选区域。

## 已实现的实战教程

已实现三个专题、16 篇操作教程。入口 `/module/ai-overseas/learn`，首页、阶段正文和全站搜索均可进入。这是学习网站的内容状态，不代表生图产品已开发、部署或产生收入。

在 AI 出海内按三个专题组织，从对应路线阶段进入，正文直接在网站阅读：

| 专题 | 要教会什么 | 练习产出 |
| --- | --- | --- |
| 找需求（02—03） | 去哪些社区、评论区和搜索结果找线索；怎样搜索、记录原话、分析竞品、访谈用户；怎样用样例和价格验证需求，决定继续或调整 | 需求证据表、竞品对照、访谈记录、验证结论 |
| 做产品与上线（04—05） | 怎样确定第一版功能、画使用流程、评估开源项目、借助 AI 开发和调试；怎样配置域名、部署、接口密钥、图片存储、统计；怎样定价、接入支付、验收、更新和回退版本 | 可访问的产品、上线检查表、成本表、支付验收记录 |
| 做增长（06—09） | 怎样选渠道、写推广内容、发布和记录来源；怎样找关键词、做页面、提交搜索引擎并检查收录；怎样分析访问、使用和付费，改善复用与收支；何时值得小额测试广告 | 渠道实验、SEO 页面与观察记录、经营复盘 |

每篇围绕一个具体问题，包含操作步骤、完整演示、读者练习、可填写模板、完成标准和常见问题。操作教程补充必要的界面说明、命令或流程图；涉及服务商条件时，核对官方资料并标明日期。

例如“找需求”不能只要求读者去社区调研，要演示如何找到卖家的商品图抱怨、区分偶发不满与反复出现的问题，并设计一次样例试用。案例用生图项目贯穿，练习允许读者替换成自己的产品。

按用户节奏实践，建议先读“如何找需求”。三块的第一版教程已可阅读；后续按实际问题补充更具体的服务商操作和真实踩坑。公众号内容从有记录的实践中提炼，不把教程演示当作实绩。

教程内容在 `src/content/overseasTutorials.ts`；页面和图解在 `src/components/overseas/OverseasTutorials.tsx`。每篇有步骤、图解、示例表格、练习、完成标准、排错；需要时提供可复制的命令或文案。

每篇练习可展开编辑，由 `src/hooks/useTutorialNotes.ts` 按专题与篇目独立保存到本机浏览器。使用 `ai-overseas-note-v1:专题ID:篇目ID`，不与九阶段勾选混用，不上传，不自动发布公众号。清除浏览器数据会丢失，页面提供复制留存。

## 每次实践后怎样更新

1. 把日志加到实战页：日期、问题、选择、做法、结果、证据、下一步。
2. 区分计划、假设、实践中和已验证结果。数据写明时间范围、样本与统计口径。
3. 把有用的方法提炼到对应阶段或知识点，更新相关模板。
4. 公众号文章围绕一个真实问题写；发布后，把文章链接关联回日志。未发布时不用假链接。
5. 更新内容日期。支付、费用和政策说明以执行时官方资料为准，记录查询日期。

## 写作要求

- 说人话，先写重点。短句短段，删套话、重复总结和多余术语。
- 术语首次出现配中文解释。抽象概念给具体例子，例如“100 位访客中 5 位付费，转化率为 5%”。
- 指南写清目标、动作、产出和验收。不要只写“掌握 SEO”。
- 流程配流程图，交互配时序图，选择配决策图，对比用表格。一张图解释一个问题，检查手机可读性。
- 生图案例只是贯穿示例，通用方法应适用于读者自己的产品。
- 不编造用户、收入、上线记录或推广成果。全局写作约束也已加入 `~/.codex/AGENTS.md`。

## 进度与模板

阶段任务和验收全部勾选，才计入“已完成阶段”。进度保存在当前浏览器的 `ai-overseas-progress-v1` 中，不与站长日志混用，也不跨设备同步。

进度键包含阶段 ID、任务类型和序号。以后调整任务顺序或含义，应迁移存储版本，避免旧勾选落到新任务上。添加描述不需要改变键。

模板允许在页面编辑、复制、下载 Markdown；不会自动保存或上传，离开前需下载。路线图下载由同一份阶段数据生成，并附 Mermaid 流程图。

## 2026-09-05 教程资料核对

- Nova：固定提交 `808175e12503dfd6d5696e278134ff33040a9929`。阅读了 README、根与前后端 package.json、环境模板、Dockerfile、Compose、server.js 的配置读取和 LICENSE 第 13 条。教程修正了只装根依赖不够的问题；本地用 3001 端口，生产示例把应用仅绑定本机，并说明持久存储与商业能力缺口。
- Google：SEO 入门指南、Search Console 网站所有权验证。教程分开说明可访问、收录、展示、点击和使用，不承诺收录或排名。

- Docker / Caddy：Ubuntu 安装与反向代理文档。命令按参考代码结构编写；未在本次任务中购买服务器、运行 Nova、部署或验证真实支付。学习网站自身的页面和练习另做浏览器验证。

维护这些教程时，更新源码版本和官方来源日期；不要把参考仓库版本与用户未来产品的实现状态混为一谈。
