# 需求雷达：产品体验调整

日期：2026-09-28。范围：本机单人版本的开始研究、阅读结果和跟进流程。没有新增真实需求验证结论。

| 原问题 | 本次调整 | 完成标准 |
| --- | --- | --- |
| 内部研究约束直接出现在标题 | 产品标题与模型研究说明分开；旧报告也显示“需求探索” | 首页历史和报告标题不再出现内部约束；导出兼容旧记录 |
| 用户先面对模型与搜索规则 | “发现需求”“研究方向”两个入口；默认发现；模型折叠到分析设置 | 无题目也可开始；切换方向不丢已填题目 |
| 统计与说明挡在问题前面 | 问题线索优先；统计、采样、请求记录放入研究详情 | 打开报告能先看到问题、出处和下一步 |
| 只有证据编号，难以判断 | 卡片直接显示相关人群、原话及释义、支持来源数、现有解决线索 | 用户不用反复跳转就能初步判断；可点出处核对 |
| 看完报告无处理动作 | 收藏、调查、排除/恢复、状态筛选、调查记录 | 操作写回报告，刷新后可恢复；备注草稿在页内切换保留 |
| 研究后重新开始不便 | “再研究一次”回填题目与查询，用户手动启动 | 不自动触发下一次收费扫描 |

保留的边界：现有来源权限与费用仍未核实；部分结果只有搜索摘要；缺少真实用户采用与付款验证；临时模式关闭服务会清空报告。界面明确提示保存限制，未以视觉优化掩盖这些条件。

验证：使用隔离的模拟报告检查旧标题、模式切换、收藏/排除、筛选、出处查看与调查记录；自动检查包含标题与旧格式导出回归。本轮不调用付费接口，不把模拟线索写入正式服务。
