# 需求雷达（浏览器本地版）

用户自行填写 Brave Key、模型 Base URL 和 API Key。配置、研究报告、收藏和已保存备注存入当前浏览器的 IndexedDB。服务端只转发请求，不保存密钥或报告，也不读取站长的模型密钥。

## 使用

1. 打开「接口设置」，填写自己的接口，确认 Brave 套餐允许保存结果。可测试连接；测试会产生少量接口用量。
2. 选择「发现需求」或「研究方向」，在分析设置中选择模型。默认 `gpt-5.6-luna`，支持预置与自定义 ID，实际可用性取决于接口提供方。
3. 开始研究后保持标签页打开。可以停止；刷新或关闭会中断，已保存材料保留，下次打开不会自动重跑。
4. 查看原话、出处、反例和下一步建议，收藏线索、保存调查备注，或导出 Markdown。

同一网站的多个标签页共用本地记录，并通过浏览器任务锁避免同时扫描。不同浏览器、设备、域名和端口的数据互不相通；清除网站数据也会清除配置与报告。密钥不是加密保险箱，同源脚本可以访问，公共电脑不建议保存。

## 本地启动

需要 Node.js 24.5+，无需增加依赖：

```sh
RADAR_PORT=4320 npm run radar
```

访问 http://127.0.0.1:4320/radar/ 。旧 4317/4318 服务中的临时报告不会自动迁移，关闭旧服务前请保留需要的报告。

网站开发代理默认连接 4320。通过 Vite 访问时，后端需设置与浏览器地址完全一致的来源，例如：

```sh
RADAR_PORT=4320 RADAR_PUBLIC_ORIGIN=http://localhost:3001 npm run radar
```

如 Vite 换了端口或使用 127.0.0.1，需相应修改来源。可通过 `RADAR_DEV_PROXY_ORIGIN` 修改 Vite 的目标服务地址。

## 部署到网站

`npm run build` 会将独立页面及资源输出到 `dist/radar/`，网站已有 `/radar/` 入口。静态托管之外，仍需部署 Node 转发服务。

1. 发布网站构建产物。
2. 在服务器启动 `RADAR_PORT=4320 RADAR_PUBLIC_ORIGIN=https://ai-superman-djy.me node radar/server.mjs`，通过进程管理器保持运行。
3. 在现有 HTTPS 网站配置中加入下面的 Nginx location，再测试连接。后端只监听本机。

```nginx
location = /radar { return 301 /radar/; }
location ^~ /radar/api/ {
    proxy_pass http://127.0.0.1:4320;
    proxy_set_header Host $host;
    proxy_set_header Origin $http_origin;
    proxy_read_timeout 100s;
    client_max_body_size 512k;
    proxy_buffering off;
}
location /radar/ { try_files $uri $uri/ =404; }
```

保持规范域名一致（例如把 www 重定向到主域名）。反向代理、监控和应用日志不得记录请求正文或密钥。接口调用时密钥会经过网站后端，随后传给用户选择的服务商；“本地保存”不代表密钥不经过服务器。

服务端只接受公网 HTTPS 上游，检查 DNS 并固定目标地址，拒绝重定向和内网地址。可选 `HTTPS_PROXY` 用于部署环境出网；不要把密钥写入前端环境变量。公网部署需按网站容量设置入口限流，目前服务内并发上限为 8。

## 研究边界

当前分析搜索摘要，不抓取网页正文。发现需求从预置领域抽样后追查候选，不能覆盖所有需求；公开线索不是客户付款验证。查询和材料会发送给对应服务商。每轮有搜索、模型、时间和 token 上限，但不代表固定费用。

## 验证与维护

```sh
npm run radar:test
npm run lint
npm run build
```

自动测试和浏览器验收使用虚构材料，不代表真实市场发现。新服务和构建使用 `web/browser-index.html` 与 `web/browser-app.js`；旧 `web/index.html`、`web/app.js` 暂留给尚在运行的旧版会话。

2026-09-28 验收：18 项自动测试、类型检查和生产构建通过。浏览器模拟验证了完整探索、配置刷新恢复、服务重启后报告保留、备注刷新保留、多标签页阻止重复扫描，以及刷新中断后不自动重跑。本轮未调用真实付费接口，也未部署公网。

## 线索质量更新

新研究保留来源背景，输出领域、角色、任务、触发条件和影响，并区分材料提及与背景推测。背景必须引用本轮已分析的来源编号；编号校验不等于语义事实核验。按背景完整度及来源数量标为待补充背景、单条反馈、多来源线索，不将链接数当独立客户数或商业价值评分。现有办法与反例分别展示。追查优先补背景、同类反馈及现有产品功能，仍沿用每轮最多三条追查查询的预算。旧报告不自动重跑或补造背景，需发起新研究获取新字段。

2026-09-29：发现需求会参考当前浏览器的历史探索，优先选择较少覆盖的领域；有历史时额外生成六条新查询，传入近期查询和问题标题以减少重复。已分析过的 URL 不再进入新一轮探索材料，研究详情展示跳过数量；不同 URL 的相似问题仍可能出现。历史只在本浏览器生效，生成搜索词时近期问题标题会发给用户配置的模型接口。背景出处编号收进卡片详情，仅保留必要的推测标记。

探索资料不足四条时，会在首轮追加最多三次跨领域宽泛查询，跳过历史资料后继续分析；总搜索仍不超过十次，补搜占用同一预算，后续追查按剩余额度执行。搜索接口报错时停止自动补搜，避免无效消耗。空报告区分接口错误、历史重复、搜索无结果和资料未形成线索，显示补搜次数。
