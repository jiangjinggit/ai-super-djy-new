## 学习目标

- 把模糊需求改成一张任务卡
- 明确允许动作、人工确认和停止条件

## 1. 一张任务卡只需要五格

| 项目 | 要写什么 |
| --- | --- |
| 目标 | 这次要解决什么问题 |
| 输入 | 允许读取哪些材料 |
| 动作 | 可以执行哪些步骤 |
| 交付 | 输出什么内容与格式 |
| 边界 | 哪里必须确认，什么情况停止 |

## 2. 一个最小例子

**目标：** 从本周会议纪要中整理待办。  
**输入：** 指定会议纪要和已有项目模板。  
**动作：** 提取决定、事项、负责人和日期，不添加外部事实。  
**交付：** 输出一张待办表。  
**边界：** 原文没有负责人或日期时标记“待确认”；不得自行补写，也不得直接发送。

## 3. 为什么停止条件重要

资料缺失时，AI 可能生成看起来合理但没有依据的内容。提前约定以下规则：

- 找不到依据就标记待确认
- 输入冲突就列出冲突点
- 任务超出允许范围就停止
- 对外或不可逆动作必须等待人确认

## 本课练习

为上一课选出的任务填写五格任务卡。第一次只允许整理或生成草稿。

完成标准：别人只看任务卡，就知道 AI 从哪里开始、交付什么，以及什么时候必须停下来。
