## 学习目标

- 只用国内 6 家模型做代码选型：`GLM / Kimi / MiniMax / 豆包 / DeepSeek / Qwen`
- 比较代码模型时，把价格一起算进去，不再只看 benchmark
- 给代码任务配出 `复杂主力 / 日常默认 / 低成本跑量 / 回退模型`

## 学完能做什么

- 能把代码任务先分角色，再回官方页面核验具体模型、价格和上下文
- 能为真实仓库建立主力、日常、跑量、回退四类模型候选
- 能用一次通过率、返工时间、可用成本和验证结果决定是否切换模型

## 核心知识

### 1. 先定角色，再选模型

先别问“谁最强”，先问“这个任务要什么角色”。

| 角色 | 典型任务 | 最该看的指标 |
| --- | --- | --- |
| 复杂主力 | 跨文件改造、关键功能、复杂 Debug | 理解深度、稳定性、一次通过率 |
| 日常默认 | 常规功能、小改动、补测试 | 速度、价格、整体均衡 |
| 低成本跑量 | 批量分析、预处理、初稿 | 输入/输出单价、吞吐 |
| 回退模型 | 主力限流、风格不合、中文协作偏多 | 切换成本、可得性、中文体验 |

### 2. 国内 6 家，先看核验维度

下表不是固定推荐榜，而是选型练习表。具体模型名、上下文、单价、套餐、缓存价和地区规则都可能变化，接入前以官方当前页面为准。

| 家族 | 先适合试什么 | 必须核验什么 | 不要怎么用 |
| --- | --- | --- | --- |
| Qwen | 中文仓库、日常编码、长上下文读仓库 | 商业模型列表、上下文分档、输入/输出/缓存价 | 不要只因中文体验好就默认全任务使用 |
| DeepSeek | 批量分析、预处理、低成本跑量候选 | 当前可用模型、缓存规则、并发和限流 | 不要把低成本候选直接用于高风险关键改动 |
| Kimi | 多步 Agent、复杂需求理解、前端/文档混合任务 | 当前模型列表、价格、批量/缓存/区域规则 | 不要无差别跑低价值批处理 |
| GLM | 系统工程、复杂工具调用、长链路任务 | GLM / Code 相关模型、上下文、计费规则 | 不要只凭单次输出判断长期默认 |
| MiniMax | 已在 MiniMax 方案内、看重生成和重构性价比 | Token Plan、Coding Plan、Pay as you go 的口径差异 | 不要把套餐、按量和 coding 方案硬比到一起 |
| 豆包 | 中文协作、前端页面、字节生态内使用 | 火山方舟控制台模型、上下文长度分档和费用 | 不要在没算输出和长上下文成本前做跑量默认 |

### 3. 比价时，别只看输入价

1. **代码任务要看输出价。** 真正写代码、补测试、生成解释时，输出 tokens 往往不少，很多模型是“输入便宜，输出不便宜”。
2. **要看长上下文阶梯价。** `Qwen` 和 `豆包` 都有明显的上下文分档；你一旦经常读大仓库，账单会变。
3. **要看套餐还是按量。** `MiniMax` 这点最明显：官网同时有 `Token Plan / Coding Plan / Pay as you go`，不要把不同计费口径硬比到一起。

### 4. 课程里的最小角色方案

不要先抄模型名，先填角色。型号变化时，这张表仍然能用。

- **日常默认：** 在中文体验、速度、成本和稳定性之间最均衡的候选
- **复杂主力：** 一次通过率更高、复杂链路更稳、愿意为质量付更多成本的候选
- **低成本跑量：** 批量摘要、预处理、初稿这类低风险任务的候选
- **回退模型：** 主力限流、风格不合、中文协作或采购约束变化时能立刻切换的候选
- **复评规则：** 任务变化、失败率上升、成本异常或官方模型/价格更新时重新测试

## 作业

拿你自己的真实仓库，选 3 类任务各跑一次：

1. 一个小改动
2. 一个中等复杂功能
3. 一个跨文件高风险改动

每类任务只记录 4 个结果：

- 一次通过率
- 返工时间
- 总 token 成本
- 你愿不愿意把它设成默认模型

交付模板：

| 任务类型 | 默认候选 | 复杂主力 | 低成本跑量 | 回退候选 | 官方核验链接 | 切换条件 |
|----------|----------|----------|------------|----------|--------------|----------|
| 小改动 |  |  |  |  |  |  |
| 中等功能 |  |  |  |  |  |  |
| 高风险跨文件 |  |  | 不建议 |  |  |  |

验收口径：任何模型名旁边都要有官方核验链接和核验日期；如果你说不出切换条件，就还没有完成选型。
