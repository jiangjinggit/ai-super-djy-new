## 学习目标

- 用三类请求验收接入链路
- 按错误类型排查，而不是盲目重试
- 建立主路由、受控回退和直连基线

## 1. 接通不等于可用

先确认下游使用 Chat Completions、Responses API 还是供应商原生接口，再按顺序验证：

1. **最小请求**：检查地址、凭据、接口和模型名
2. **代表性输入**：检查上下文、格式、流式输出或工具调用
3. **真实任务**：检查结果质量、耗时和实际工作流兼容性

只返回 HTTP 200，不能证明真实任务可长期使用。

## 2. 常见错误怎么处理

| 错误 | 优先检查 | 处理原则 |
| --- | --- | --- |
| 401 / 403 | 凭据、项目或工作区权限 | 修正配置前不要重试 |
| 404 | 路径、API 版本、模型名或映射 | 对照官方端点说明 |
| 429 | 请求、令牌、并发或用量限制 | 按官方说明有限退避 |
| 5xx | 上游或网关暂时异常 | 有上限地重试或切备用路线 |
| timeout | 网络、请求规模、上游或代理耗时 | 分层记录耗时，缩小请求定位 |

涉及写入、发信、支付等副作用时，重试前必须确认请求是否能安全重放。

## 3. 回退不是随便换一个模型

建议准备三类路线：

- **主路由**：已经通过真实任务验收
- **受控回退**：只处理明确的暂时性错误
- **直连基线**：网关异常或核验原生能力时使用

跨供应商回退前，要写清能力、成本、数据区域和内容政策差异。鉴权、参数和路径错误不能靠自动回退解决。

## 4. 最小验收表

| 验收项 | 结果 | 备注 |
| --- | --- | --- |
| 最小请求 | 通过/失败 | 地址、凭据、接口、模型名 |
| 代表性输入 | 通过/失败 | 上下文、格式、工具调用 |
| 真实任务 | 通过/失败 | 质量、耗时、稳定性 |
| 失败演练 | 通过/失败 | 重试、备用路线、恢复方式 |

## 本课练习

选择一条非生产链路完成四项验收，并记录一次失败的排查过程。

完成标准：关键能力全部通过；失败时知道该修配置、有限重试、切换路线，还是交给人工处理。
