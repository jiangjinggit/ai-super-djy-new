## 学习目标

- 理解网关不是透明管道
- 建立敏感数据、凭据、日志和路由四条底线
- 知道如何核验模型映射变化

## 1. 请求数据会经过网关

Prompt、上下文、工具参数和返回结果都会经过接入层。选择第三方服务前，至少确认：

- 谁在运营，是否有清楚的服务说明
- 是否记录请求内容，保留多久，谁能访问
- 模型来源和路由是否可解释
- 服务中断或停止运营时如何迁移

来源、日志和边界解释不清时，不要把它放进敏感或关键流程。

## 2. 只保留四条治理底线

### 敏感任务

私有代码、客户资料、合同、生产配置和高权限动作，优先官方直连或完全自控链路。

### 凭据隔离

使用项目、工作区、服务账号或网关虚拟 Key 区分测试、正式和不同调用方。只改 Key 名称但仍共享权限与预算，不算隔离。

### 日志最小化

默认只记录排查所需的时间、路由、耗时、状态码和用量统计。确需查看请求内容时，应脱敏、限制访问并设置短保留期。

### 路由与预算控制

只开放已验证的模型映射，设置预算或限额，并写清出现异常账单、模型错配或质量突变时如何暂停。

## 3. 不要用输出风格证明模型身份

同一个模型的输出会受版本、系统指令、采样参数和网关改写影响。固定样本只能帮助发现变化，不能证明底层模型身份。

更可靠的核验依据包括：

- 响应中的模型或路由元数据
- 供应商账单和调用记录
- 网关模型映射配置
- 服务方公开说明或合同约定
