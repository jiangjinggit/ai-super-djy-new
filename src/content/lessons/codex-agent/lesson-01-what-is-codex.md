# Codex 是什么，它和聊天 AI、Claude Code 有什么区别

## 本课目标

学完这一课，你要能用自己的话说明三件事：

- Codex 为什么不是普通聊天框。
- 哪些任务适合交给 Codex 执行。
- Codex 和 Claude Code、Cursor、普通 ChatGPT 的分工边界在哪里。

## 核心认知

Codex 是 OpenAI 面向软件工程任务的编码代理体系。它不只是生成一段代码，而是围绕真实仓库完成一组动作：读取文件、理解项目规则、制定计划、修改代码、运行命令、验证结果，并把改动整理成可以审查的交付物。

普通聊天 AI 更像顾问。你问它一个问题，它给你解释、示例或建议。Codex 更像执行者。你把它放进一个仓库任务里，它需要面对真实文件、真实依赖、真实测试和真实风险。

这也意味着 Codex 的使用重点不是“问得更玄”，而是“任务定义得更清楚”。越是涉及真实仓库，越要写清范围、禁止事项、验证方式和回退方式。

## 与 Claude Code 的关系

Claude Code 和 Codex 都属于编码代理。Claude Code 模块里讲过的 5 步执行法、上下文管理、安全边界和任务拆分，仍然适用于 Codex。

差异主要在入口和生态：

- Codex 更贴近 OpenAI 的 App、IDE、CLI、Cloud tasks 组合。
- Claude Code 有自己的 CLI、Desktop、Cowork、skills、hooks 等生态。
- Cursor、Windsurf、Kiro 等工具更偏 IDE 内即时编辑体验。

不要急着只选一个工具。更成熟的策略是：用同一套任务契约和验收标准管理不同工具。

## 练习

写下 5 个你想交给 Codex 的真实任务。每个任务后面标注：

- 是否需要读仓库。
- 是否需要改文件。
- 是否需要运行命令。
- 是否需要联网或访问外部系统。
- 失败后能不能快速回退。

## 验收标准

你能把 5 个任务分成三类：

- 只适合聊天咨询。
- 适合本地 CLI/IDE 执行。
- 适合 Cloud tasks 异步处理。

如果你暂时分不清，就先把任务降级为只读分析。Codex 的第一步永远应该是读懂上下文，而不是直接动手。

## 常见误区

误区一：把 Codex 当成更聪明的搜索引擎。  
正确做法：让它基于你的仓库、文档和命令输出工作。

误区二：第一天就让它重构整个项目。  
正确做法：先只读，再小改，再验证，再逐步扩大范围。

误区三：因为是 OpenAI 官方工具，就默认所有结论都对。  
正确做法：关键结论必须有文件证据、命令输出或官方文档来源。
