# CLI 快速上手：从只读分析到第一处小改动

## 本课目标

用 Codex CLI 在真实项目里完成两件事：

- 一次只读分析。
- 一次低风险小改动。

不要跳过只读分析。它是建立信任的第一步。

## 第一次启动

进入你的项目目录后再启动 Codex CLI。第一条指令建议这样写：

```text
请先只读分析这个项目。读取 README、主要配置文件和 src 目录结构，说明：
1. 这个项目是什么技术栈；
2. 本地开发和构建命令可能是什么；
3. 你认为最重要的目录有哪些；
4. 你不确定的地方请标注为假设。
不要修改任何文件。
```

观察它是否真的基于文件回答。如果它开始凭经验猜测，就要求它指出证据文件。

## 第一处小改动

选择一个失败成本低的任务，例如：

- 改一处错别字。
- 补一个小组件测试。
- 修一个样式溢出。
- 给 README 补一段运行说明。

指令中要明确写出：

- 只改哪些文件。
- 不改哪些文件。
- 修改前先给计划。
- 修改后运行哪个验证命令。
- 最终输出 diff 摘要和风险。

## 记录三件事

每次任务都保存：

1. 原始指令。
2. 实际 diff。
3. 验证结果。

这三件事能帮你复盘问题：到底是你没说清、Codex 没读懂，还是项目本身缺少测试。

## 练习

在一个非生产关键仓库里完成一次小改动。推荐任务：“给一个页面或函数补充一条说明性文档，不改变行为。”

## 验收标准

任务完成后检查：

- `git diff` 只包含计划内改动。
- Codex 没有修改锁文件、配置文件或无关文件。
- 至少完成一次 lint、typecheck、test、build 或手动验证。
- 最终总结包含改动、验证和残留风险。

如果任何一项不满足，先不要扩大使用范围。
