# AGENTS.md：给 Codex 的项目说明书

## 本课目标

写出一份基础版 AGENTS.md，让 Codex 每次进入项目时都能读到同一套规则。

## AGENTS.md 放什么

AGENTS.md 不是项目百科，也不是临时任务清单。它应该放 Codex 长期需要遵守的项目规则：

- 项目目标和用户。
- 技术栈和关键目录。
- 常用开发、测试、构建命令。
- 代码风格和命名约定。
- 禁止事项。
- 验收标准。
- PR 或提交要求。

如果信息一周后就会过期，不要写进 AGENTS.md。临时计划应该写在任务描述里。

## 推荐结构

```markdown
# 项目说明

## 项目目标

## 常用命令

## 目录结构

## 编码约定

## 测试与验证

## 禁止事项

## 输出与 PR 要求
```

这 7 段已经够用。不要第一版就写成几十页。

## 维护原则

每次 Codex 犯了可复现的错误，都问自己：这是不是应该变成一条规则？

例如：

- 它总是顺手改格式化：加“不要做全仓格式化”。
- 它总是修改锁文件：加“未经明确允许不要修改 lock file”。
- 它不知道测试命令：把测试命令写进常用命令。

同时也要删掉过期规则。过长、互相冲突的 AGENTS.md 会降低执行质量。

## 练习

给当前项目写一份 AGENTS.md 草案，至少包含：

- 3 条常用命令。
- 3 条禁止事项。
- 1 条验证要求。
- 1 条 PR 输出格式。

## 验收标准

新开一次 Codex 会话，让它读取 AGENTS.md 后回答：

- 这个项目的验证命令是什么？
- 它不能做哪些操作？
- 修改完成后应该怎么汇报？

如果回答准确，说明 AGENTS.md 起到了基本作用。
