# Prompt 与任务契约：别只说“帮我优化一下”

## 本课目标

把模糊指令改成可执行、可审查的任务契约。

## 任务契约六段式

一个高质量 Codex 任务通常包含六段：

1. 背景：为什么要做。
2. 任务：具体要完成什么。
3. 范围：可以读写哪些文件。
4. 禁止：不能做哪些事。
5. 验收：怎么判断完成。
6. 输出：最后如何汇报。

## 坏指令与好指令

坏指令：

```text
帮我优化一下首页。
```

好指令：

```text
请优化首页移动端首屏的按钮布局。
范围：只允许修改 src/pages/HomePage.tsx 和相关样式文件。
目标：按钮在 375px 宽度下不换行溢出，文字清晰可点。
禁止：不要改路由、不要改文案含义、不要全局重构。
验证：运行 npm run lint 和 npm run build，并说明手动检查结果。
输出：总结改动、验证结果和残留风险。
```

差别不在措辞，而在可验证性。

## 四类常用契约

Bug 修复：必须有复现步骤、期望行为、实际行为。  
功能开发：必须有用户故事、验收标准、技术边界。  
代码审查：必须有关注重点、风险等级、输出格式。  
文档补全：必须有读者对象、覆盖范围、禁止臆造。

## 练习

把下面三条指令改写成任务契约：

- 帮我修一下登录问题。
- 帮我整理一下这个项目。
- 帮我把代码写得更规范。

## 验收标准

改写后的每条指令都应该包含：

- 允许范围。
- 禁止事项。
- 验收方式。
- 输出格式。

如果缺少其中任何一项，Codex 就容易自由发挥。
