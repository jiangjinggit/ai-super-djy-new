# Codex Cloud tasks：把低耦合任务交给云端并行

## 本课目标

学会判断哪些任务适合 Cloud，哪些任务应该留在本地。

## Cloud tasks 的价值

Cloud tasks 的核心价值是异步和并行。你可以把一个清晰、低耦合、可验收的仓库任务交给云端环境，让 Codex 在后台执行，并通过结果或 PR 审查。

适合的任务：

- 补测试。
- 修局部 Bug。
- 更新文档。
- 做小范围重构。
- 给多个独立文件补类型或说明。
- 准备 PR 描述和迁移说明。

## 不适合的任务

不适合 Cloud 的任务：

- 需求还没想清。
- 需要长时间实时交互。
- 强依赖本机私有环境。
- 需要访问生产秘钥。
- 涉及生产数据库或客户隐私。
- 失败后难以回退。

云端任务不是万能后台员工。它更像一个可以并行处理明确 issue 的工程同事。

## 任务拆分方法

一个大任务不要直接丢给 Cloud。先拆成：

- 可独立描述。
- 可独立验证。
- 可独立失败。
- 不互相修改同一片核心代码。

例如“优化整个设置页”可以拆成：

1. 修复移动端布局。
2. 给表单校验补测试。
3. 更新设置页 README。

## 练习

把你当前的一个大需求拆成 3 个 Cloud task。每个 task 写：

- 输入。
- 允许修改范围。
- 禁止事项。
- 验收标准。
- 失败处理。

## 验收标准

每个 Cloud task 都满足：

- 不依赖本机私有文件。
- 不需要生产秘钥。
- 失败后不会污染主分支。
- 结果可以通过 PR 或 diff 审查。
