# MCP 与外部工具：给 Codex 接上必要上下文

## 本课目标

理解 MCP 的价值和风险，学会先接低风险工具，再逐步扩大能力。

## MCP 解决什么问题

仓库里的代码不是全部上下文。真实任务经常还需要：

- GitHub issue。
- 项目文档。
- 设计稿说明。
- 浏览器页面。
- 内部知识库。
- 监控或日志摘要。

MCP 可以把这些工具和数据源以更规范的方式接入 Codex。

## 最小权限原则

每接一个工具，都要问：

- 它能读什么？
- 它能写什么？
- token 在哪里保存？
- 如何撤销权限？
- 是否有审计记录？
- 是否包含敏感数据？

新手阶段优先只读，不要一上来给写权限。

## 适合先接的场景

比较适合起步的 MCP 场景：

- 只读读取项目文档。
- 只读读取 issue 或 PR。
- 读取本地指定目录。
- 浏览器截图或页面检查。

不适合起步：

- 生产数据库。
- 支付后台。
- 客户隐私系统。
- 无审计日志的内部工具。

## 练习

设计一个 MCP 接入方案，不一定马上执行。写清：

- 要接什么工具。
- 解决什么任务。
- 授权范围。
- 只读还是可写。
- 如何验证。
- 如何撤销。

## 验收标准

你能解释为什么这个 MCP 值得接，也能解释为什么没有开放更大权限。
