# 配置与 Profiles：把不同任务的默认行为分开

## 本课目标

学会把不同任务的默认行为分开，不用一套权限跑所有事。

## 为什么要分配置

只读审查、日常开发、隔离实验、Cloud 准备任务，它们需要的权限完全不同。

如果你用同一套默认配置处理所有任务，就会出现两个问题：

- 低风险任务拿到了过高权限。
- 高风险任务缺少明确确认点。

配置的目的不是炫技，而是降低犯错成本。

## 四类 profile 思路

readonly-review：

- 用于代码审查和仓库体检。
- 默认只读。
- 不执行写入命令。

daily-dev：

- 用于日常小改动。
- 允许工作区写入。
- 高风险命令需要确认。

sandbox-lab：

- 用于实验性依赖、脚本和方案探索。
- 放在隔离目录或临时分支。
- 明确失败后删除或回滚。

cloud-ready：

- 用于准备 Cloud tasks。
- 重点是任务描述、环境要求、验证命令和 PR checklist。

## 配置原则

先少后多。先写 AGENTS.md 和审批策略，再根据稳定流程补 MCP、默认命令和 profile。

不要把还没验证过的流程写成默认自动行为。

## 练习

给自己的项目设计 4 个 profile。每个 profile 写：

- 适用任务。
- 默认权限。
- 禁止事项。
- 验证方式。
- 何时停止。

## 验收标准

你能在发起任务前判断该用哪个 profile，并知道为什么。
