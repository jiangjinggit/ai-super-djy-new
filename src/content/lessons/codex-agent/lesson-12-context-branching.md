# 上下文、分支与回退：让每次改动都可恢复

## 本课目标

建立 Codex 任务前后的工程卫生习惯：看状态、分支隔离、审查 diff、保留回退路径。

## 任务前检查

每次让 Codex 改代码前，先确认：

- 当前分支是什么。
- `git status` 是否干净。
- 哪些改动是用户已有改动。
- 本次任务允许改哪些文件。
- 验证命令是什么。

如果工作区不干净，要告诉 Codex：哪些文件不能碰，哪些改动不能覆盖。

## 分支策略

建议：

- 一个任务一个分支。
- 一个意图一个 diff。
- 大任务拆成多个小 PR。
- 不把格式化、重构、功能改动混在一起。

Codex 很适合小步提交。它不适合在缺少边界时一次性重写大半个项目。

## 停止规则

出现这些情况，让 Codex 停下：

- 它开始修改计划外文件。
- 验证失败且原因不明。
- 它要求更高权限但理由不充分。
- 它要删除文件、改配置、安装依赖或推送代码。
- 它的解释和仓库事实矛盾。

## 回退方式

常见回退方式：

- 撤销单个文件改动。
- 丢弃临时分支。
- revert 一个 commit。
- 恢复锁文件。
- 回到任务前保存的 patch。

关键不是永远不出错，而是出错后能回到已知状态。

## 练习

写一份自己的任务前检查表和停止规则。把它放进 AGENTS.md 或团队文档。

## 验收标准

你能拿最近一次 Codex 改动回答：

- 它从哪个状态开始。
- 改了哪些文件。
- 怎么验证。
- 如果失败怎么回退。
