# 安全治理：团队该怎样允许 Codex 改代码

## 本课目标

从个人使用升级到团队治理：明确哪些任务能用 Codex，哪些必须人工处理，哪些需要安全或法务确认。

## 个人层

个人要先做到：

- 不把秘钥贴进任务。
- 任务前看 git status。
- 高风险动作先确认。
- 任务后看 diff。
- 验证通过再提交。

个人习惯不稳，团队治理很难落地。

## 团队层

团队需要统一：

- AI 可处理任务白名单。
- 禁止任务清单。
- PR 审查标准。
- Cloud tasks 使用门槛。
- 敏感目录和配置文件保护。
- 失败复盘方式。

例如：允许 Codex 补测试、修文档、小范围 Bug；禁止它直接改生产配置、数据库迁移、权限系统和支付逻辑。

## 组织层

涉及客户数据、合规、供应链安全、生产环境、商业机密时，需要组织级政策。

课程可以提供工程习惯，但不能替代公司安全、法务和合规判断。

## 使用政策草案

你可以从这 5 段开始：

```markdown
## 允许任务
## 禁止任务
## 必须审批
## PR 审查
## 日志与复盘
```

不要写成空泛口号。每条都要能执行。

## 练习

为你的团队写一页 Codex 使用政策。即使只有你一个人，也按团队标准写。

## 验收标准

新人读完政策后，能判断：

- 什么任务可以交给 Codex。
- 什么操作必须停下问人。
- AI PR 合并前要检查什么。
