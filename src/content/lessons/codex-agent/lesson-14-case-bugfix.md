# 实战案例 A：开发者用 Codex 修一个真实 Bug

## 场景

你发现登录后跳转错误：用户成功登录后没有进入仪表盘，而是停留在登录页。

你要用 Codex 完成一次标准 Bug 修复，不允许顺手重构。

## 输入准备

给 Codex 的信息应包括：

- 复现步骤。
- 期望行为。
- 实际行为。
- 相关页面或路由文件。
- 最近是否改过登录逻辑。
- 验证命令。

示例：

```text
请帮我修复登录成功后仍停留在登录页的问题。
复现：...
期望：...
实际：...
范围：优先读取 src/pages/LoginPage.tsx、src/router、auth 相关文件。
禁止：不要重构认证系统，不要改接口签名，不要引入新依赖。
先只读分析，再给修复计划，我确认后再改。
验证：npm run lint && npm run build。
```

## 执行过程

第一步，只读分析。要求 Codex 输出可能原因和证据文件。  
第二步，确认最小修复计划。  
第三步，执行修改。  
第四步，运行验证。  
第五步，总结根因、改动和风险。

## 审查重点

重点看：

- 是否只改了登录相关文件。
- 是否修改了路由或认证边界。
- 是否有新的测试或手动验证说明。
- 是否把假设写成了事实。
- 是否有回退方式。

## 练习

找一个真实小 Bug，完整跑一遍这个流程。不要选择涉及生产数据、支付、权限系统的 Bug。

## 验收标准

最终交付必须包含：

- 根因。
- 修改文件。
- 验证结果。
- 未覆盖风险。
- 回退方式。

如果缺少任意一项，就让 Codex 补齐后再进入下一任务。
