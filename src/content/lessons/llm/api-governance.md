## 这节课你要拿到什么

- 一套 Key 分离和命名规则
- 一张调用记录表
- 一组预算分级和降档规则
- 一个把真实调用反哺模型地图的回看节奏

> 上节课你画好了模型地图，这节课解决接入后的管理问题：Key 怎么管、成本怎么控、记录怎么留，以及这些记录怎样帮助你下次选模型。

## 第一步：把 Key 分开（⏱ 10 分钟）

不管你是个人还是小团队，只要开始接 API，第一件事就是把 Key 分开。

### 最少分 3 个 Key

| Key 名称 | 用途 | 默认额度 | 禁止事项 |
|----------|------|----------|----------|
| test-[你的名字] | 开发测试、试新模型、调提示词 | 小额度 | 不接正式工作流 |
| daily-[你的名字] | 日常工作流、正式任务 | 中额度 | 不跑批量实验 |
| auto-[你的名字] | 自动化流程、批量任务 | 按任务量设上限 | 不直接执行高风险动作 |

如果平台支持项目、环境或服务账号，也按同样逻辑拆：测试、日常、自动化不要混用。

### Key 存放规则

- 存在密码管理器里，不要存在聊天记录或截图里
- 不要写进公开代码仓库、教程素材或共享文档
- 如果用 `.env` 文件，确保 `.gitignore` 里有 `.env`
- 新工具先接 `test` Key，连续稳定后再接 `daily` 或 `auto`

✅ 完成标准：你至少有 test 和 daily 两个分开的 Key，每个都有明确用途和额度上限。

## 第二步：建一张调用记录表（⏱ 10 分钟）

不需要一开始上复杂平台，用飞书多维表格就够。

### 在飞书多维表格里建表

新建一个多维表格，命名为“API 调用记录”，加这些字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| 日期 | 日期 | 调用日期 |
| 任务 | 单选 | 摘要 / 写作 / 提取 / 分析 / 批量 / 其他 |
| 模型 | 单选 | 真实调用的模型名或网关别名 |
| 模型角色 | 单选 | 默认 / 高质量 / 低成本 / 回退 |
| Key 类型 | 单选 | test / daily / auto |
| 输入量 | 数字 | 大约多少 token，粗估即可 |
| 输出量 | 数字 | 大约多少 token |
| 耗时 | 数字 | 秒 |
| 预算档 | 单选 | 低 / 中 / 高 |
| 成本 | 数字 | 元或美元，币种保持一致 |
| 结果可用 | 单选 | 是 / 否 / 需返工 |
| 返工量 | 数字 | 需要改多少分钟 |
| 异常原因 | 文本 | 失败、限速、超时、格式错等 |

### 示例数据

| 日期 | 任务 | 模型角色 | Key | 输入量 | 输出量 | 耗时 | 预算档 | 成本 | 结果可用 | 返工量 |
|------|------|----------|-----|--------|--------|------|--------|------|----------|--------|
| 3/25 | 周报摘要 | 默认 | daily | 2000 | 800 | 15s | 中 | 以账单为准 | 是 | 5 分钟 |
| 3/25 | 竞品分析 | 高质量 | daily | 8000 | 3000 | 45s | 高 | 以账单为准 | 需返工 | 25 分钟 |
| 3/26 | 批量分类 | 低成本 | auto | 50000 | 5000 | 30s | 低 | 以账单为准 | 是 | 10 分钟抽查 |

只要你手工记录 10-20 次，就能发现哪类任务最烧钱、哪个模型返工最多、哪些调用其实不值得。

✅ 完成标准：你有一张调用记录表，至少记了 3 条真实数据。

## 第三步：给不同任务设预算档（⏱ 10 分钟）

按任务设预算，这样选模型就有边界。

| 预算档 | 任务类型 | 默认模型角色 | 单次上限怎么定 | 超过后怎么办 |
|--------|----------|--------------|----------------|--------------|
| 低预算 | 批量分类、预处理、简单摘要 | 低成本模型 | 以你的月预算倒推 | 降采样、分批、抽查 |
| 中预算 | 内容提纲、方案框架、信息整理 | 默认模型 | 看返工时间是否可接受 | 优化提示词或换默认模型 |
| 高预算 | 复杂分析、对外高质量内容、关键文档 | 高质量模型 | 看交付价值和风险 | 需要人工确认和复盘 |

预算档不是固定金额，而是决策边界。不同平台、模型、地区和缓存规则都会变化，具体价格只以官方当前页面和你的账单为准。

在调用记录表里加一个“预算档”字段，每周汇总看看各档花了多少。

✅ 完成标准：你的调用记录表里有预算档字段，知道每类任务的成本上限和超限动作。

## 第四步：写降档和升档规则（⏱ 10 分钟）

预算治理不是一味省钱，而是把钱花在值得的地方。

### 降档规则

出现这些情况，考虑从默认模型降到低成本模型：

- 任务是批量提取、分类、清洗，人工抽查即可
- 输出只作为中间材料，不直接交付
- 连续 10 次记录显示默认模型质量明显过剩
- 该任务成本超过预算，但返工率没有明显改善

### 升档规则

出现这些情况，考虑从默认模型升到高质量模型：

- 输出要对外发布、给客户或进入关键决策
- 默认模型连续多次遗漏事实或格式不稳定
- 人工返工时间明显高于模型成本差异
- 任务包含复杂推理、多约束方案或严肃代码审查

把这些规则写进模型地图，不要只写在脑子里。

✅ 完成标准：每个常用任务都有“什么时候降档”和“什么时候升档”的说明。

## 第五步：给高风险动作做日志（⏱ 5 分钟）

只要流程里涉及这些动作，就一定要留日志并人工确认：

- 写文件，尤其是覆盖已有内容
- 发消息，如邮件、群通知、客户回复
- 调外部接口，如支付、数据同步、生产系统
- 批量更新数据
- 读取或处理包含 secrets、客户资料、合同、私有仓库的上下文

日志至少记录：

```text
触发人：[你的名字]
执行时间：[日期时间]
模型角色：[默认/高质量/低成本/回退]
模型名或网关别名：[实际调用项]
动作：[做了什么]
输入摘要：[大概内容，不贴敏感原文]
输出摘要：[大概结果]
是否人工确认：[是/否]
是否需要复盘：[是/否]
```

个人用户可以直接在飞书文档里建一个“高风险操作日志”页面。等以后做自动化时，再把日志接进工具或网关。

✅ 完成标准：你知道哪些动作需要留日志，有一个记录的地方。

## 每周 10 分钟回看节奏

每周固定回看一次调用记录，按这个顺序看：

1. 哪类任务花费最高
2. 哪个任务返工量最高
3. 哪些失败来自模型、哪些来自提示词或输入质量
4. 有没有低预算任务误用了高质量模型
5. 有没有高价值任务为了省钱导致返工更多
6. 模型地图是否需要调整

回看不是为了追责，而是为了让选型表越来越接近真实工作。

## 个人用户的 5 条最小治理规则

直接照抄：

1. 所有实验调用都先走 test Key，不直接碰正式流程
2. 新流程连续跑满 5 次稳定后，再接入 daily Key
3. 批量和自动化流程单独走 auto Key，并设置上限
4. 任何涉及外发、写入、支付、批量修改的动作都必须人工确认
5. 每周花 10 分钟回看调用记录，把成本、返工和异常写回模型地图

## 案例：小张第一次接 API 的踩坑经历

小张是产品经理，想用 API 自动生成竞品周报。他一开始直接把同一个 Key 接进所有工具。

### 第 1 周：没做治理

| 问题 | 发生了什么 |
|------|------------|
| Key 混用 | 测试和正式用同一个 Key，测试时把额度烧完了，正式流程断了 |
| 没有记录 | 不知道哪次调用花了多少钱，月底账单吓一跳 |
| 没有预算 | 简单摘要用了高质量模型，批量任务没有成本边界 |
| 没有返工记录 | 只知道“贵”，不知道贵是否减少了人工修改 |

### 第 2 周：按这节课的方法补治理

| 改进 | 做了什么 |
|------|----------|
| Key 分离 | 建了 test / daily / auto 三个 Key |
| 调用记录 | 记录任务、模型角色、成本、返工量和异常 |
| 预算分级 | 批量摘要先走低成本，深度分析才升档 |
| 周回顾 | 每周看一次记录，发现一批任务可以降档 |
| 回填模型地图 | 把“竞品摘要可降档、客户方案需升档”写成规则 |

> “我以前以为治理就是省钱。后来发现更重要的是知道钱花在哪、返工省在哪、什么时候该换模型。”

## 常见翻车

### 翻车 1：Key 写进公开仓库

❌ 错误做法：把 API Key 直接写在代码里，推到公开仓库。

为什么错：公开仓库很容易被扫描，Key 泄露后会带来账单和数据风险。

✅ 正确做法：Key 存在 `.env` 或密钥管理器里，公开仓库不要包含密钥和真实配置。

### 翻车 2：所有任务都用高质量模型

❌ 错误做法：觉得“贵的肯定好”，所有任务都用高质量模型。

为什么错：简单摘要、分类和清洗不需要同一档能力。你省下的预算应该留给关键任务。

✅ 正确做法：按预算档和任务价值分配模型。低预算任务先用低成本模型，关键交付才升档。

### 翻车 3：从不回看调用记录

❌ 错误做法：接了 API 之后就不管了，月底看账单才发现超支。

为什么错：很多无效调用、重复调用、参数写错和模型错配会悄悄烧钱。

✅ 正确做法：每周看一次调用记录，检查成本、返工、失败率和模型地图是否需要调整。
